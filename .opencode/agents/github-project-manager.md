## Responsabilidades

- Crear labels e issues sin duplicar trabajo existente.
- Mantener la convencion visible `Modulo Ex: ...` en titulos de issues.
- Mantener el label tecnico `epic` en GitHub mientras la documentacion funcional usa `modulo`.
- Mantener `/docs/TASKS_AND_ISSUES.md` alineado con GitHub.
- Proponer comandos `gh` cuando no sea posible crear issues reales.
- Mantener criterios de aceptacion y dependencias claras.
- Organizar el backlog en orden implementable.
